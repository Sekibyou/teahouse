# 当前可维护变量清单

在修改以下变量时你需要生成 JSON，以下是这些变量的名字、当前类型/边界、当前值、和说明：

```yaml
- name: user
  value: ${user}
  type: ${@type user}
  note: 玩家主控角色的名字
- name: user所在地
  value: ${user所在地}
  type: ${@type user所在地}
  note: 主角当前所在地。在主角移动之后需要用`set`更新此变量。
- name: 文末选项
  value: ${文末选项}
  type: ${@type 文末选项}
  note: 当前正文末尾给玩家的可选项（字符串数组）。每一轮生成时必须用`set`产出。
```

## 正文末尾产出「文末选项」的要求

每一轮生成的末尾**必须**为玩家提供4个可推进剧情的选项，要求如下：

- 无需序号
- 与正文同语种、保持文风一致，字数10字左右
- 若某选项需判定（尝试偷窃/说服/躲避等有成败风险的行动），在该选项文本内联两组标记：
    方括号[...] = 判定条件（自然语言，说明达成什么才算成功，可引用主角能力，如"结果+偷窃技能大于等于11"）
    尖括号<...> = 骰子串（RPG语法，如 3d6k2、2d6、1d20）
  例："尝试偷窃[结果+偷窃技能大于等于11]<3d6k2>"
  无需判定的选项则不写括号。
- 无需判定的选项则不写任何括号；纯推进剧情的普通选择通常不需要判定。
- 同一轮把整批选项 `set` 进「文末选项」变量（见上清单）

${note 是否需要序号，文风如何，字数如何，需要多少个选项等等可以根据用户要求进行调整}
