# 楼层系统与流程编排

楼层 (Floor) 是 Teahouse 的核心内容单元。本文档定义楼层系统的运作机制和导演的编排流程。

## 楼层的定义

一个楼层是一个独立的内容单元，对应一个 `.md` 文件。它类似小说中的"一章"或聊天中的"一条消息"。

### 楼层的特性

- **一个楼层可一次性生成**——AI 完整输出一个楼层的内容
- **一个楼层可分多次续写**——AI 分多次追加到同一文件，直到完成
- **一个楼层可被修改优化**——导演或工具可编辑已有楼层
- **一个楼层完成后触发 git commit**——计入楼层计数

### 楼层文件

```
floors/
├── floor-001.md    # 第 1 层
├── floor-002.md    # 第 2 层
└── ...
```

## 楼层的生命周期

```
当前楼层 (floors/floor-NNN.md)
  │
  ├─ 初始生成（AI 输出正文，使用 generate-floor skill）
  │
  ├─ [可选] 续写循环
  │   ├─ 用户/导演认为内容不足
  │   ├─ AI 继续追加正文到同一文件
  │   └─ 直到满足楼层完成条件
  │
  ├─ [可选] Refine 循环
  │   ├─ 格式修正
  │   ├─ 一致性检查
  │   └─ 细节优化
  │
  └─ 楼层完成
      ├─ floors/floor-NNN.md 定稿
      ├─ 更新 logs/summaries.yaml（追加楼层总结）
      ├─ git commit（floor commit）
      └─ 递增楼层计数

      └─ [检查是否需要总结]
          ├─ 否 → 进入下一层
          └─ 是 → 触发总结流程
```

## 楼层完成条件

楼层完成条件由 `teahouse.md` 中的楼层配置定义。skill 在生成时引用这些数值：

```
skill prompt 中说：
  "根据 teahouse.md 的楼层配置，目标字数约 3000 字，
   达到后可考虑完成，超出 5000 字建议截断。"
```

典型配置项：
- **目标字数**：达到即可考虑完成
- **最少字数**：未达到时建议续写
- **最大字数**：超出时建议截断或拆分
- **内容完整性**：场景/对话自然结束

创作者在原型中预设，用户在实例的 teahouse.md 中随时调整。

## 总结流程

总结是一个特殊流程，不占用楼层编号，但触发 git commit 和上下文重组。

### 触发条件

总结触发条件由 `teahouse.md` 中的总结规则定义，skill 在生成时引用这些数值：

```
skill prompt 中说：
  "根据 teahouse.md 的总结触发条件，
   当前距离上次总结已有 N 层，检查是否需要触发总结。"
```

典型规则：
1. **建议阈值**：每 7 层建议一次总结（teahouse.md 中配置）
2. **强制阈值**：超过 10 层未总结时强制建议
3. **用户手动触发**：用户可随时要求总结

### 总结流程

```
总结触发
  │
  ├─ 加载 skills/summarize/（总结 skill）
  │
  ├─ 通读自上次总结以来的所有楼层
  │
  ├─ 压缩旧楼层正文为小段总结
  │   └─ 写入 logs/summaries.yaml
  │
  ├─ 变量变更处理
  │   ├─ 识别关键变量变更
  │   │   └─ 追加 logs/change-log/
  │   ├─ 识别非关键变量变更
  │   │   └─ 更新 variables/active.yaml
  │   └─ 确保 active.yaml 与变更链一致
  │
  ├─ git commit（summary commit）
  │
  └─ 上下文重组
      ├─ 旧楼层正文 → 仅保留总结
      ├─ 最近楼层保持完整
      ├─ 变量系统按最新版本加载
      └─ 继续下一层
```

### 上下文重组的效果

```
总结前：
  1~7 层总结（小段文本）
  8~10 层正文全文
  variables/active.yaml（对应第 10 层状态）
  提示：现在是第 11 层

总结后：
  1~7 层总结（不变）
  8~10 层总结（新增，替代原来的正文）
  11~13 层正文全文
  variables/active.yaml（对应第 13 层状态，已更新）
  提示：现在是第 14 层
```

## Git 提交流程

每个实例创建时自动执行 `git init`，实例是一个独立的 git 仓库。

### GitCommit 工具

使用 `GitCommit(message)` 工具执行提交。内部执行 `git add -A && git commit -m "message"`，自动暂存所有变更。

### 楼层提交

```
GitCommit("floor-NNN: 简短描述")
```

### 总结提交

```
GitCommit("summary-NNN: 覆盖楼层 M~N 的总结")
```

### 提交历史示例

```
floor-001: 林月离开星罗城
floor-002: 路遇苏河
floor-003: 抵达青竹镇
summary-001: floor-001~003 总结，变量已更新
floor-004: 镇中打探消息
floor-005: 夜探藏书阁
summary-002: floor-004~005 总结，变量已更新
```

### 分支管理

使用 `GitBranch(action, name?)` 管理分支，用于剧情分支存档和回档：

- **创建分支**：`GitBranch("create", "分支名")` 基于当前 HEAD 创建
- **切换分支**：`GitBranch("switch", "分支名")` 切换到已有分支，文件随之切换
- **列出分支**：`GitBranch("list")` 查看所有分支
- **删除分支**：`GitBranch("delete", "分支名")` 删除已合并的分支

分支切换时，`sessions/` 目录不纳入版本控制，当前对话上下文不受影响。

## 楼层计数器

楼层计数仅关注 `floor-` 前缀的 commit，`summary-` 前缀跳过。当前楼层号存储在变量系统中供导演读取。

## 导演的编排责任

1. **管理上下文窗口**——在上下文膨胀到限制前触发总结
2. **保证楼层质量**——通过 Refine 循环确保输出符合 skill 定义的质量要求
3. **维护变量一致性**——总结时确保变量变更被正确捕捉
4. **管理文件状态**——避免楼层文件写入冲突
5. **按需加载 skill**——在合适的阶段加载对应的 skill 提示词
