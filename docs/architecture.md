# Teahouse 架构总览

Teahouse 是一个基于 Harness Engineering 思想的小说创作/即时文字冒险引擎。不同于 Silly Tavern 等前端驱动的 prompt 工程方案，Teahouse 采用后端驱动的工具编排架构。

## 核心思想

**增量上下文 + 定期压缩**

每一轮生成产生新内容 → 上下文逐渐膨胀 → 触发总结压缩旧轮 → 上下文精简 → 继续生成。

这与 Claude Code 的上下文管理同构：

| Claude Code | Teahouse |
|---|---|
| 对话变长 → 自动压缩早期内容 | 楼层积累 → 总结轮压缩旧轮 |
| 压缩后关键信息保留 | 旧轮正文 → 一小段总结 + 变量变更 |
| 无法恢复压缩前细节 | 可通过 change log + 原文按需回溯 |

## 原型与实例

Teahouse 区分原型 (Prototype) 和实例 (Instance) 两个层级。

### 原型 (Prototype)

原型是一个 `.zip` 文件，类似酒馆的角色卡。由创作者设计，包含：

- `teahouse.md`（初始配置模板）
- `settings/`（世界观、角色设定）
- `skills/`（提示词技能包——正文生成、总结归纳等）
- `variables/`（初始变量定义和 schema）

原型不包含游玩中产生的数据（楼层文件、变更日志等）。

### 实例 (Instance)

原型解压后复制一份到存档目录即成为实例：

```
原型 .zip
  │
  └─ 解压 → 复制到存档目录 → 实例（独立运行）
```

一个实例包含：
- `teahouse.md`
- `settings/`
- `skills/`（原型自带 + 游玩中新建的）
- `variables/`（初始 + 游玩变更）
- `floors/`（正文）
- `logs/`（总结 + 变更日志）
- `current/`（工作区）

**实例化后完全独立**，不跟随原型更新。游玩过程中 teahouse.md 和 skill 可以大幅变更。

### Skill

Skill 是提示词包，包含指令、例子和参考资料。类似 Vibe Coding 的 skill 概念。

Skill 的职责是**方法论**——告诉导演"怎么写"，但不写死具体数字。
具体数值（楼层字数、总结频率等）引用 `teahouse.md` 中的配置。

```
skill prompt 中说：
  "根据 teahouse.md 中定义的楼层字数要求生成正文，内容需达到目标字数"
  而非
  "生成约 3000 字的正文"
```

内置核心 skill：
- **正文生成** (`skills/generate-floor/`) — 告诉导演如何撰写正文
- **总结归纳** (`skills/summarize/`) — 告诉导演如何执行总结

Skill 的特性：
- 创作者可在原型中预装 skill，实例化时一并复制
- 游玩中可临时创建新 skill
- 创建的 skill 可导出复用

### teahouse.md

每个实例一份的配置文件，始终实时注入导演上下文。职责是**配置**——告诉导演"这个实例的要求是什么"：

- 楼层字数、总结频率等数值参数
- 变量定义和关键变量标记
- 实例元信息（关联原型、楼层计数等）

teahouse.md 由创作者在原型中预设初始值，游玩中可随时调整。

## 名词体系

| 名词 | 含义 |
|---|---|
| **原型 (Prototype)** | 创作者设计的 `.zip` 包，类似角色卡 |
| **实例 (Instance)** | 原型解压后独立运行的存档 |
| **Skill** | 提示词包，包含指令、例子和参考资料 |
| **楼层 (Floor)** | 一个独立的内容单元，对应一个 `.md` 文件 |
| **楼层计数** | 正文轮次的编号，从 001 开始递增 |
| **总结 (Summary)** | 触发 git commit + 上下文重组，不计入楼层计数 |
| **导演 (Director)** | 执行编排流程的 AI 主体 |
| **变量系统** | 存储和追踪故事中需要记忆的所有信息 |
| **teahouse.md** | 实例级系统核心配置，始终实时注入 |

## 核心流程

### 正常楼层生成

```
准备阶段 →
  ├─ 加载 teahouse.md（系统配置，始终最新）
  ├─ 加载 settings/（世界观、角色设定）
  ├─ 加载 skills/generate-floor/prompt.md（正文生成 skill）
  ├─ 加载最近 N 层总结 → 理解前情
  ├─ 加载最近 M 层正文全文 → 近期细节
  ├─ 加载 variables/active.yaml → 当前状态
  └─ 组装上下文

生成阶段 →
  ├─ 调用最强模型生成正文
  ├─ 写入 current/draft.md
  ├─ Refine 循环（格式修正、一致性检查）
  └─ 确定最终版本

提交阶段 →
  ├─ 写入 floors/floor-NNN.md
  ├─ 更新 logs/summaries.yaml
  ├─ 检查是否需要触发总结（引用 summarize skill 的规则）
  ├─ git commit（floor commit）
  └─ 递增楼层计数
```

### 总结流程

```
总结触发（由 summarize skill 的规则判定）→
  ├─ 加载 skills/summarize/prompt.md（总结 skill）
  ├─ 压缩旧楼层正文为小段总结
  ├─ 解析变量变更 → 更新 active.yaml
  ├─ 关键变量变更 → 追加 change log
  ├─ 写入 logs/summaries.yaml
  ├─ git commit（summary commit）
  └─ 上下文重组：
      ├─ 旧楼层正文 → 保留总结
      ├─ 变量系统：初始值 + 变更链 = 当前值
      └─ 继续下一轮
```
